우선순위: MoSCoW — Must(없으면 출시 불가) / Should / Could / Won't
모든 스토리는 PRD의 Given/When/Then 수용 기준을 가진다. 상세는 docs/prd.md 4절 참조.

## Must — 1차 출시 필수 (현실적 MVP)
| ID | 제목 | 근거 | 예상 크기 |
|---|---|---|---|
| US-001 | 회원가입 | Q1-b, Q4-c | 1~2일 |
| US-002 | 로그인 / 로그아웃 | Q4-c | 1일 |
| US-003 | 비로그인 열람 및 로그인 게이트 | Q4-c | 1일 |
| US-004 | 레시피 등록 | Q2-a | 2~3일 |
| US-005 | 레시피 목록·상세 조회 | Q2-a | 2일 |
| US-006 | 레시피 수정 | Q2-a | 1~2일 |
| US-007 | 레시피 삭제 | Q2-a | 0.5일 |

| US-009 | 레시피에 식재료 연결 | Q5-c | 2일 |
| US-010 | 레시피 검색·필터 | Q2-d | 2일 |

## Should — 여력 시 1차, 아니면 2차 우선
| ID | 제목 | 근거 | 예상 크기 |
|---|---|---|---|
| US-011 | 보유 식재료(재고) 관리 (수량·유통기한) | Q2-c | 2일 |
| US-012 | 레시피 상세에서 부족한 재료 표시 | Q5-c | 2일 |

## Could — 여유 시 진행 (계산 복잡도 높음)
| ID | 제목 | 근거 | 예상 크기 |
|---|---|---|---|
| US-013 | 보유 재료 기반 레시피 추천/필터 | Q2-e | 2~3일 |

## Won't — 이번 범위 제외
| 항목 | 근거 |
|---|---|
| 장보기 목록 / 자동 쇼핑리스트 | Q3-a 명시적 제외 |
| 영양성분·칼로리 계산 | Q3 미선택 |
| 레시피 공개 공유·댓글·좋아요 등 소셜 | Q3 미선택 |
| 식단 캘린더 / 주간 플래너 | Q3 미선택 |
| 외부 쇼핑몰·배달 연동 | Q3 미선택 |
| 팀/가족 공동 편집, 관리자 콘텐츠 운영 | Q1 다수 개인 회원 모델 |

## 의존 관계 (구현 순서 참고)
- US-001/002/003 (인증) → 등록·수정 계열의 선행
- US-008 (식재료 마스터) → US-009(레시피-재료 연결) → US-011(재고) → US-012(부족 재료) → US-013(추천)
- US-004~007 (레시피 CRUD)은 US-009와 함께 개발
- US-010 (검색)은 US-004/005 이후

## 비고
- Must 합계 약 13~16일 + Should 4일 = 반응형(Q7-c)·소규모(Q6-a) 기준 약 2~4주 MVP.
- 사용자가 Q2에서 5개 전부를 필수로 요청했으므로, Should/Could 강등은 PRD 5절 Open Question으로 사용자 확인 대상.

## 의존 관계 (구현 순서)
- ③(US-014~017) → ①(US-018) → ②(US-019~022)  *(조리시간·재고필드가 대시보드·연결의 선행)*
- US-015 별점은 **신규 recipe_ratings 테이블**(회원별 집계) 필요 → BE 영향 최대.
- US-022는 US-019(부족재료 전달)·US-017(보관위치 단계)에 의존.
- 매칭 판정은 전 스토리 공통 "매칭률 100%(동일 단위 비교)" 단일 규칙 *(Q3-a)*.

## 비고
- 전 신규 컬럼 nullable·백필 없음(Q4-a), 신규 엔드포인트 additive → 기존 화면 회귀 0 목표.
- 데이터/계약 영향 개괄은 PRD v2.3.0-5 참조(backend-dev G2 입력).
