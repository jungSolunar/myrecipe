# 레시피 & 식재료 관리 웹서비스 PRD
버전: 0.2 | 작성일: 2026-07-24 | 상태: Approved (G1 통과, 사용자 승인 2026-07-24)

> 근거: 모든 주요 결정은 `docs/requirements-interview.md`의 답변(Q1~Q7)과 연결된다.

## 1. 문제 정의
- **누가**: 요리를 하는 여러 일반 회원 (각자 자기 레시피/식재료를 관리) *(Q1-b)*
- **상황**: 자신의 레시피를 흩어진 메모·캡처로 관리해 다시 찾기 어렵고, 집에 어떤 재료가 있는지 파악이 안 돼 중복 구매·재료 낭비가 생긴다.
- **불편**: (1) 내 레시피를 구조화해 저장·검색할 곳이 없다. (2) 보유 재료와 레시피가 연결되어 있지 않아 "지금 있는 재료로 뭘 만들 수 있는지" 알기 어렵다.

## 2. 목표 & 성공 지표
- **목표(정성)**: 개인이 자신의 레시피와 보유 식재료를 한 곳에서 등록·검색·관리하고, 보유 재료 기준으로 레시피를 활용할 수 있게 한다.
- **지표(정량, 소규모 기준 — Q6-a)**:
  - 회원이 레시피를 등록하고 다시 검색해 찾는 핵심 플로우 성공률 ≥ 95%
  - 레시피 상세에서 "내 재고 대비 부족한 재료" 표시가 재고 데이터와 100% 일치
  - 레시피 목록/검색 응답 체감 지연 1초 이내 (레시피 수백 개 규모 기준)
  - 등록/수정 시 비로그인 사용자가 로그인 유도 화면으로 100% 안내됨

## 3. Non-goals (이번에 하지 않는 것)
- 장보기 목록 / 자동 쇼핑리스트 생성 — **명시적 제외** *(Q3-a → MoSCoW Won't)*
- 영양성분·칼로리 계산 *(Q3, 미선택 → 이번 범위 밖)*
- 레시피 공개 공유·댓글·좋아요 등 소셜 기능 *(Q3, 미선택 → 이번 범위 밖; 열람 자유이나 "공유 발행"은 아님)*
- 식단 캘린더 / 주간 식단 플래너 *(Q3, 미선택)*
- 외부 쇼핑몰·배달 연동 *(Q3, 미선택; Q7 외부 연동 제약 없음)*
- 팀/가족 공동 편집, 관리자 콘텐츠 운영 *(Q1에서 다수 개인 회원 선택 → 공유 그룹·관리자 모델 제외)*

## 4. 유저스토리

> **범위 배분 주의(중요):** 사용자는 Q2에서 5개 기능(레시피 CRUD·식재료 CRUD·검색/필터·재고관리·보유재료 추천)을 모두 MVP로 선택했다. 그러나 규모는 소규모(Q6-a)이고 현실적 MVP(약 2~4주)를 목표로 하므로, 서로 의존관계가 있는 기능을 계층화했다. 기반이 되는 CRUD·검색·연동은 **Must**, 재고 관리와 부족 재료 대조는 **Should**, 계산 복잡도가 높은 "보유 재료 기반 추천"은 **Could**로 배분한다. 이 배분은 planner의 권고이며, 사용자가 5개 전부를 1차 출시 필수로 고정하려면 일정이 늘어남 → 5절 Open Questions 참조.

### 인증 (Q4-c: 열람 자유, 등록·수정만 로그인)

#### US-001: 회원가입 [Must]
As a 방문자, I want 이메일/비밀번호로 회원가입, so that 내 레시피와 재료를 개인 계정에 저장할 수 있다.
**수용 기준**
- Given 미가입 방문자 When 유효한 이메일·비밀번호로 가입 요청 Then 계정이 생성되고 로그인 상태가 된다
- Given 이미 등록된 이메일 When 동일 이메일로 가입 시도 Then 중복 안내 메시지가 표시되고 가입이 거부된다

#### US-002: 로그인 / 로그아웃 [Must]
As a 회원, I want 로그인·로그아웃, so that 내 데이터에 안전하게 접근하고 세션을 종료할 수 있다.
**수용 기준**
- Given 가입된 회원 When 올바른 자격증명으로 로그인 Then 인증되어 등록·수정 기능이 활성화된다
- Given 잘못된 자격증명 When 로그인 시도 Then 실패 안내가 표시되고 인증되지 않는다
- Given 로그인 상태 When 로그아웃 Then 세션이 종료되고 열람 전용 상태로 돌아간다

#### US-003: 비로그인 열람 및 로그인 게이트 [Must]
As a 방문자, I want 로그인 없이 레시피를 열람, so that 가입 전에 서비스를 둘러볼 수 있다. 단 등록·수정은 로그인 후에만 가능하다. *(Q4-c)*
**수용 기준**
- Given 비로그인 방문자 When 레시피 목록/상세를 조회 Then 로그인 없이 열람할 수 있다
- Given 비로그인 방문자 When 등록/수정/삭제를 시도 Then 로그인 화면으로 유도되고 동작은 수행되지 않는다

### 레시피 관리 (Q2-a)

#### US-004: 레시피 등록 [Must]
As a 회원, I want 제목·조리 단계·사진(선택)·카테고리와 재료를 포함한 레시피를 등록, so that 내 레시피를 구조화해 보관한다. *(Q2-a, 사진은 Q6-a에 따라 선택 항목)*
**수용 기준**
- Given 로그인 회원 When 제목·조리 단계를 입력하고 저장 Then 레시피가 내 계정에 생성되어 목록에 나타난다
- Given 필수값(제목) 누락 When 저장 시도 Then 검증 오류가 표시되고 저장되지 않는다
- Given 사진 미첨부 When 저장 Then 사진 없이도 정상 저장된다 (사진은 선택)

#### US-005: 레시피 목록·상세 조회 [Must]
As a 사용자, I want 레시피 목록과 상세를 조회, so that 등록한 레시피 내용을 확인한다.
**수용 기준**
- Given 레시피가 존재 When 목록 화면 진입 Then 레시피들이 제목·대표정보와 함께 표시된다
- Given 특정 레시피 When 상세 진입 Then 제목·재료·조리 단계·사진(있으면)·카테고리가 모두 표시된다

#### US-006: 레시피 수정 [Must]
As a 회원, I want 내 레시피를 수정, so that 내용을 최신 상태로 유지한다.
**수용 기준**
- Given 내가 등록한 레시피 When 필드를 수정하고 저장 Then 변경 내용이 상세에 반영된다
- Given 다른 회원의 레시피 When 수정 시도 Then 권한 없음으로 차단된다

#### US-007: 레시피 삭제 [Must]
As a 회원, I want 내 레시피를 삭제, so that 불필요한 레시피를 정리한다.
**수용 기준**
- Given 내가 등록한 레시피 When 삭제 확인 Then 레시피가 목록에서 제거된다
- Given 다른 회원의 레시피 When 삭제 시도 Then 권한 없음으로 차단된다

### 식재료 관리 (Q2-b, Q5)

#### US-008: 식재료 마스터 등록·관리 [Must]
As a 회원, I want 식재료(이름·분류·기본 단위)를 마스터 목록으로 등록·수정·삭제, so that 레시피와 재고에서 재사용해 오타·중복을 막는다. *(Q2-b, Q5-c의 "마스터에서 선택" 전제)*
**수용 기준**
- Given 로그인 회원 When 재료명·분류·단위를 입력해 저장 Then 식재료가 마스터 목록에 추가된다
- Given 동일 이름의 재료가 이미 존재 When 중복 등록 시도 Then 중복 안내가 표시된다
- Given 레시피/재고에서 참조 중인 재료 When 삭제 시도 Then 참조 영향이 안내된다

#### US-009: 레시피에 식재료 연결 [Must]
As a 회원, I want 레시피 작성 시 식재료 마스터에서 재료를 선택해 수량과 함께 연결, so that 재료 데이터가 구조화되어 검색·재고 대조에 쓰인다. *(Q5-c)*
**수용 기준**
- Given 레시피 편집 화면 When 마스터에서 재료를 검색·선택하고 수량을 입력 Then 해당 재료가 레시피 재료 목록에 연결된다
- Given 마스터에 없는 재료 When 새 재료명을 입력 Then 마스터에 신규 등록 후 연결하도록 안내된다

### 검색 (Q2-d)

#### US-010: 레시피 검색·필터 [Must]
As a 사용자, I want 레시피를 이름·카테고리·재료 기준으로 검색·필터, so that 원하는 레시피를 빠르게 찾는다. *(Q2-d)*
**수용 기준**
- Given 레시피가 존재 When 이름 키워드로 검색 Then 일치하는 레시피만 목록에 표시된다
- Given 카테고리/재료 필터 선택 When 적용 Then 조건에 맞는 레시피만 표시된다
- Given 일치 결과 없음 When 검색 Then 빈 결과 안내가 표시된다

### 재고 관리 & 부족 재료 대조 (Q2-c, Q5-c)

#### US-011: 보유 식재료(재고) 관리 [Should]
As a 회원, I want 내가 보유한 식재료의 수량·유통기한을 등록·수정, so that 집에 있는 재료를 파악한다. *(Q2-c)*
**수용 기준**
- Given 로그인 회원 When 마스터 재료를 선택해 보유 수량·유통기한을 저장 Then 내 재고 목록에 추가된다
- Given 재고 항목 When 수량을 0으로 수정 또는 삭제 Then 보유 목록에서 제거/소진 처리된다

#### US-012: 레시피 상세에서 부족한 재료 표시 [Should]
As a 회원, I want 레시피 상세에서 내 재고와 대조해 부족한 재료를 표시, so that 무엇을 더 사야 하는지 알 수 있다. *(Q5-c)*
**수용 기준**
- Given 재고 데이터가 있는 로그인 회원 When 레시피 상세 진입 Then 레시피 재료 중 재고가 없거나 수량이 부족한 항목이 "부족"으로 표시된다
- Given 모든 재료를 충분히 보유 When 상세 진입 Then "재료 충족"으로 표시된다
- Given 비로그인 방문자 When 상세 진입 Then 부족 재료 표시는 숨겨지고 로그인 시 제공됨을 안내한다

### 추천 (Q2-e)

#### US-013: 보유 재료 기반 레시피 추천/필터 [Could]
As a 회원, I want 내 보유 재료로 만들 수 있는(또는 거의 만들 수 있는) 레시피를 추천·필터, so that 지금 있는 재료를 활용한다. *(Q2-e)*
**수용 기준**
- Given 재고 데이터가 있는 로그인 회원 When "만들 수 있는 레시피" 필터 적용 Then 보유 재료로 모든 재료가 충족되는 레시피만 표시된다
- Given 일부만 보유 When 추천 목록 조회 Then 부족 재료 수가 적은 순으로 정렬되어 표시된다

## 5. 확인 필요 (Open Questions)
- **[범위/일정] — 확정됨 (2026-07-24 사용자 승인)**: 계층화 동의. Must(US-001~010) 1차 출시 → Should(US-011~012) → Could(US-013) 순차 진행.
- **[데이터] — 확정됨 (2026-07-24 사용자 승인)**: 식재료 마스터는 **회원 개인별** 마스터로 구성한다 (전 회원 공용 아님).
- **[데이터] (미해결, 이후 과제)**: 재고 수량 단위와 레시피 요구 수량 단위의 환산(예: g ↔ 개) 정책 미정. US-012 "부족" 판정은 동일 단위 기준으로 우선 구현하고, 단위 환산은 이후 과제로 이관.
- **[비기능] (designer/backend 단계 확정)**: 사진 저장 방식·용량 상한 미정. 소규모(Q6-a) 기준 사진은 선택 항목이며 상세 정책은 G2에서 확정.

## 6. 비기능 요구사항 (참고)
- **플랫폼**: PC·모바일 반응형 모두 대응 *(Q7-c)* — 모든 주요 화면은 모바일 뷰포트에서도 사용 가능해야 한다.
- **규모**: 소규모(레시피 수백 개 이하), 사진 선택적 *(Q6-a)*.
- **외부 제약**: 특별한 외부 시스템 연동·법적 제약 없음 *(Q7-c)*.
