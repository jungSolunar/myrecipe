## 기술 스택
- 프론트엔드: React 18 + TypeScript + Vite (정적 SPA, MSW 데모 목 포함)
- 백엔드: Python + FastAPI (ASGI, uvicorn/gunicorn)
- DB: SQLite (마이그레이션 자동 적용, soft delete)
- 인증: 세션 쿠키(HttpOnly, 운영 시 Secure)
- API: `/api/v1` 프리픽스, 표준 에러 포맷 `{error:{code,message,details}}`

## 알려진 제한 (Known Limitations)
- **재고 관리 미포함** (US-011, Should) — 스키마 일부만 존재, 화면/기능 미제공.
- **부족 재료 표시 미포함** (US-012, Should).
- **보유 재료 기반 추천 미포함** (US-013, Could).
- **단위 환산 미지원** — 식재료 수량은 입력 단위 그대로 저장, 단위 간 자동 환산 없음.
- **전용 헬스체크 엔드포인트 없음** — liveness는 `GET /openapi.json`으로 대체 (다음 릴리스에서 `/api/v1/health` 추가 권장).
- **SQLite 동시성 제약** — 소규모 전제. 고동시성 쓰기에는 부적합, 워커 수 낮게 유지.

## 품질 게이트 (릴리스 시점)
- 백엔드: pytest 통과
- 프론트엔드: lint / test / build 통과, API 계약 위반 필드 없음
- 회귀 하네스: greenfield(베이스라인 미존재, exit 2 = 경고 후 통과). 릴리스 확정 후 사용자가 최초 베이스라인 캡처 예정.

## 배포 후 후속 조치 (사용자)
1. `deploy/README.md`의 배포 절차 수행 (마이그레이션은 기동 시 자동).
2. 릴리스 확정 후 최초 회귀 보호 베이스라인 캡처: `./harness/baseline.sh` (**사용자 전용**).
   - 이후 v1 화면/기능이 회귀 보호 대상에 편입되고, CI 하네스가 침범(exit 1)을 차단한다.
