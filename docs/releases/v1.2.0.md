- 릴리스: **v1.2.0** — Recipe Box (레시피 & 식재료 관리 웹서비스)
- 릴리스 일자: **2026-07-25**
- 범위: **Could US-013** (범위 계층화의 3차)
- 이전 릴리스: [v1.1.0](v1.1.0.md) (Should US-011~012) · [v1.0.0](v1.0.0.md) (Must US-001~010)
- 배포/롤백 절차: `deploy/README.md`

## 포함 기능 (Could US-013)

| ID | 기능 | 설명 |
|---|---|---|
| US-013 | 보유 재료 기반 레시피 추천/필터 | 레시피 목록에 "만들 수 있는 레시피" 토글 추가. 내 재고와 대조해 부족 재료가 0인 레시피만 필터(`available_only`)하고, 부족 재료 적은 순으로 정렬(`sort=missing_asc`). 각 카드에 "부족 N개" 배지 표시 |

## 계약 변경 (additive)

- `RecipeListItem` 스키마에 optional `missing_count`(nullable integer) 필드 **추가**.
  - 추천/필터 컨텍스트에서 해당 레시피의 부족 재료 개수를 나타냄. 토글 off(기본) 시에는 표기하지 않음.
  - **하위 호환 유지** — 기존 소비자는 새 optional 필드를 무시하면 됨. 응답 필드 삭제·타입 변경·필수화 없음.
- `available_only` / `sort` 쿼리 파라미터는 v1.0.0 계약에 이미 존재 → 파라미터 계약 변경 없음.
- `openapi.yaml` `info.version`을 **1.2.0**으로 갱신.

## 이전 버전(v1.1.0) 대비 변경점

- 레시피 목록에 **"만들 수 있는 레시피" 토글** 추가 — 내 재고 기준 부족 재료 0인 레시피만 필터 + 부족 적은 순 정렬.
- 목록 카드에 **"부족 N개" 배지**(추천 컨텍스트) 추가.
- 계약은 **additive-only**: `RecipeListItem.missing_count`(optional, nullable) 추가 외 변경 없음.
- **기본 동작(토글 off)은 v1.1.0과 동일** — 기존 목록·검색·필터 화면과 기능은 그대로 보존.

## 알려진 제한 (Known Limitations)

- **단위 환산(g ↔ 개 등) 미지원** — 동일 단위 기준으로만 보유/부족을 판정. 단위가 다르면 정확한 대조 불가.
- **`missing_asc` 정렬 시 소규모 전제** — 정렬 기준 산출을 위해 대상 집합을 전량 계산한 뒤 페이지네이션. 대량 데이터에는 부적합(소규모 전제 유지).
- **dev MSW 목에 `/inventory`·추천 계산 없음** — 개발용 목 데모에서는 추천/필터가 동작하지 않으며, 실제 백엔드에 연결해야 동작.
- v1.0.0/v1.1.0 제한 중 유효한 항목 유지: 전용 헬스체크 엔드포인트 없음(`GET /openapi.json`로 대체), SQLite 동시성 제약(소규모 전제).

## 품질 게이트 (릴리스 시점)

- 백엔드: pytest 통과.
- 프론트엔드: lint / test / build 통과, API 계약 위반 필드 없음.
- 회귀 하네스: 보호 파일 무결성 + API 계약 호환(additive) + 특성화 테스트. US-013 사전 승인된 보호 파일 편집(recipes.py, 목록/필터바 등) 반영을 위해 릴리스 확정 후 재베이스라인 예정.

## 업그레이드 / 배포 시 주의

- **DB 마이그레이션 불필요** — 스키마 변경 없음(기존 재고·레시피·재료 테이블 그대로 사용).
- 프론트엔드(정적 SPA)와 백엔드를 **함께 재배포**하면 신규 토글/필터가 노출됨.
- 롤백은 v1.1.0 아티팩트로 FE·BE를 되돌리면 됨(스키마 무변경으로 데이터 롤백 불필요). 절차는 `deploy/README.md` 참조.
