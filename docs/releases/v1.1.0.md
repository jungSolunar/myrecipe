# Release Notes — v1.1.0 (재고 관리)

- 릴리스: **v1.1.0** — Recipe Box (레시피 & 식재료 관리 웹서비스)
- 릴리스 일자: **2026-07-25**
- 범위: **Should US-011 ~ US-012** (범위 계층화의 2차)
- 이전 릴리스: [v1.0.0](v1.0.0.md) (Must US-001~010)
- 배포/롤백 절차: `deploy/README.md`

## 포함 기능 (Should US-011~012)

| ID | 기능 | 설명 |
|---|---|---|
| US-011 | 보유 식재료(재고) 관리 | 마스터 재료의 보유 수량·유통기한 등록·수정·삭제 화면 신규 추가 (`/inventory`) |
| US-012 | 부족 재료 표시 활성화 | 레시피 상세에서 내 재고와 대조해 보유/부족 배지 표시 (기구현 로직이 재고 데이터로 동작) |

## 변경/추가 파일 요약

- **프론트엔드 (신규)**
  - `web/src/features/inventory/` — 재고 관리 화면 일체 (InventoryPage, InventoryTable/Row, InventoryAddForm, ExpiryBadge, useInventory, expiry 유틸 + 특성화 테스트)
  - `web/src/api/inventory.ts` — 재고 API 클라이언트 (기존 `/inventory` BE API 연동)
- **프론트엔드 (순수 추가 편집 — 사전 승인됨, US-011)**
  - `web/src/App.tsx` — `/inventory` 라우트 추가
  - `web/src/components/Header.tsx` — 재고 네비 항목 추가
- **백엔드**
  - 변경 없음. `/inventory` API는 v1.0.0에 이미 존재하며 그대로 사용.
- **문서/운영**
  - `docs/releases/v1.1.0.md` (본 문서), `README.md` 갱신
  - `harness/manifest.json` — web 특성화 테스트 명령 수정 (`--watchAll` 제거, vitest run 정합)

## 이전 버전(v1.0.0) 대비 변경점

- 신규 화면 **재고 관리(`/inventory`)** 추가 — 헤더 네비에서 진입.
- 레시피 상세의 **부족 재료 표시(US-012)** 가 재고 데이터로 실제 동작(v1.0.0에서는 재고 데이터 부재로 비활성 상태였음).
- 백엔드 API/스키마 변경 없음 (additive-only). 기존 화면·기능은 보존.

## 알려진 제한 (Known Limitations)

- **단위 환산(g ↔ 개 등) 미지원** — 동일 단위 기준으로만 보유/부족을 판정. 단위가 다르면 정확한 대조 불가.
- **보유 재료 기반 추천 미포함** (US-013, Could) — 다음 범위(로드맵).
- **dev MSW 목에 `/inventory` 핸들러 없음** — 개발용 목 데모에서는 재고 화면이 목 데이터로 동작하지 않으며, 실제 백엔드에 연결해야 동작.
- v1.0.0 제한 중 유효한 항목 유지: 전용 헬스체크 엔드포인트 없음(`GET /openapi.json`로 대체), SQLite 동시성 제약(소규모 전제).

## 품질 게이트 (릴리스 시점)

- 백엔드: pytest 통과 (변경 없음)
- 프론트엔드: lint / test / build 통과, API 계약 위반 필드 없음
- 회귀 하네스: 보호 파일 무결성 + API 계약 호환 + 특성화 테스트. US-011 사전 승인된 순수 추가 편집(App.tsx, Header.tsx) 반영을 위해 릴리스 확정 후 재베이스라인 예정.

## 업그레이드 / 배포 시 주의

- **DB 마이그레이션 불필요** — 재고 테이블은 v1.0.0 스키마에 이미 존재. 스키마 변경 없음.
- 무중단 배포 가능(백엔드 변경 없음). 프론트엔드 정적 SPA만 재배포하면 신규 화면이 노출됨.
- 롤백은 v1.0.0 아티팩트로 프론트엔드만 되돌리면 됨 (백엔드 롤백 불필요). 절차는 `deploy/README.md` 참조.
