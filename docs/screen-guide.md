# 화면 가이드 (Screen Guide)

기준 버전: **v2.3.0** · 갱신일: **2026-07-26**

"어떤 기능이 어느 화면에서 어떻게 동작하는가"를 **화면 기준**으로 정리한 기획문서다.
릴리스 노트(무엇이 바뀌었나)·user-flows(흐름도)와 달리, 사용자·팀원이 화면에서 기능 위치를 찾는 참조용이다.
근거: 실제 라우트(`web/src/App.tsx`), 화면 컴포넌트, `docs/releases/*`, `docs/prd.md`.

## 화면 지도 (IA)

| 경로 | 화면 | 접근 권한 | 진입점 |
|---|---|---|---|
| `/home` | **홈/개요 (대시보드)** | **로그인 필요** | 헤더 사이드바 "개요 › 홈" (**v2.3.0 신규**) |
| `/` | 레시피 목록 | 열람 자유 | 브랜드 로고 "🥕 레시피 상자", 앱 기본 진입 |
| `/recipes/:id` | 레시피 상세 | 열람 자유 | 목록 카드 클릭 |
| `/recipes/new` | 레시피 등록 | 로그인 필요 | 목록 "+ 새 레시피" |
| `/recipes/:id/edit` | 레시피 수정 | **본인만** | 상세 "수정" |
| `/ingredients` | 식재료 마스터 | 로그인 필요 | 헤더 "식재료 마스터" |
| `/inventory` | 내 재고 | 로그인 필요 | 헤더 "내 재고" |
| `/login` | 로그인 | 비로그인 | 헤더 "로그인" 버튼, 게이트 유도 |
| `/signup` | 회원가입 | 비로그인 | 로그인 화면 "계정 없음" |

> 비로그인은 목록·상세만 열람 가능. 홈/개요·등록·수정·삭제·재고·마스터 진입 시 로그인 게이트로 유도되고
> 로그인 후 원래 화면으로 복귀(`returnTo`). (US-003)
>
> **`/home`은 v2.3.0 신규 추가지만 기존 index(`/`)=레시피 목록은 불변**이다. 앱 기본 진입은 여전히 레시피 목록이며,
> 홈/개요는 로그인 회원이 헤더 "개요 › 홈"으로 진입하는 별도 대시보드다. (US-018)

## 화면별 상세

### 홈/개요 — 대시보드 (`/home`) · **v2.3.0 신규**
- **접근 권한**: **로그인 필요**(개인 재고 기반 집계, 비로그인은 로그인 게이트로 유도)
- **진입점**: 헤더 사이드바 "개요 › 홈" 링크. (index `/`=레시피 목록과 별개 화면)
- **표시 상태**: 로딩(스켈레톤) / 오류(재시도) / **첫 방문 빈 상태**(등록 레시피·재고가 모두 0이면 "레시피와 재고를 등록해 현황을 채워보세요" + [+ 새 레시피]·[재고 등록]) / 정상.

| 동작 | 화면 위치 | 방식 | 조건/예외 | US | 도입 |
|---|---|---|---|---|---|
| KPI — 등록 레시피 | 상단 KPI 카드 4종 중 1 | "N개" + 카테고리 분포(상위 3) 부가 | — | US-018 | v2.3.0 |
| KPI — 지금 만들 수 있는 레시피 | KPI 카드 | **매칭률 100% 레시피 수**(성공색), "매칭률 100%" 부기 | 재고 대조 기반 | US-018 | v2.3.0 |
| KPI — 내 재고 | KPI 카드 | 보유 재고 "N종" | — | US-018 | v2.3.0 |
| KPI — 임박 재료(D-3) | KPI 카드 | 유통기한 D-day ≤ 3 재료 "N종"(경고색) | — | US-018 | v2.3.0 |
| 패널 — 지금 만들 수 있는 레시피 | 좌측 패널 | 매칭률 100% 레시피 목록(조리시간·평균 평점·"지금 가능" 배지), 클릭 시 상세 이동 | 없으면 "재고를 더 등록해 보세요" 안내 | US-018 | v2.3.0 |
| 패널 — 유통기한 임박 | 우측 상단 패널 | 임박 재료 목록(보관위치 pill·D-day 배지) | 없으면 "임박한 재료가 없어요" | US-018 | v2.3.0 |
| 패널 — 최근 추가한 레시피 | 우측 하단 패널 | 최근 등록 레시피 목록, 클릭 시 상세 이동 | 없으면 "최근 추가한 레시피가 없어요" | US-018 | v2.3.0 |

## 알려진 제한 (화면 동작 관련)
- 추천/부족 판정은 **동일 단위 기준**만 대조(g↔개 등 환산 미지원). **보관위치·유통기한은 매칭 판정에 반영하지 않는다**(기존 동일 단위 규칙 유지).
- **공개 vs 로그인 구분(v2.3.0)**: 조리시간·평균 평점은 **비로그인에게도 표시되는 공개 정보**다. 반면 **입력·개인화**(별점 매기기, 조리시간 등록/수정, 홈 대시보드·역탐색·매칭률 진행바·부족 재료 추가)는 **로그인 필수**다.
- **별점은 회원별 평점 집계**(평균·평가 수)이며 **1인 1평점**(재저장 시 갱신)이다. **리뷰 코멘트/텍스트는 미지원**(수치 평점만).
- 홈 대시보드 "지금 만들 수 있는"·매칭 진행바의 판정 단위는 **매칭률 100%**(부족 0)다.
- 개발용 MSW 목에는 `/inventory`·추천 계산이 없어 **실제 백엔드 연결 시에만** 추천 토글이 동작한다.
- 추천 정렬(`missing_asc`)은 소규모 데이터 전제.
