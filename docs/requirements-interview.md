# 요구사항 인터뷰: 레시피 & 식재료 관리 웹서비스
상태: CLOSED
라운드: 1/2 (1라운드로 충분 — 핵심 불확실성 없음, Phase 2 진행)

## 요청 원문
"레시피 등록 및 관리, 식재료 관리를 하는 웹서비스를 구성하려고 해."

## 내가 이해한 것 (확인용 요약)
- 웹 기반 서비스로, 레시피를 **등록·조회·수정·삭제**하고 관리할 수 있다.
- 식재료(재료)를 **관리**하는 기능이 함께 있다 (재료 목록/재고/보유 여부 등으로 추정).
- 레시피와 식재료가 서로 **연동**될 가능성이 있다 (예: 레시피가 어떤 재료를 쓰는지).
- 아직 대상 사용자, 인증 필요 여부, 기능의 정확한 범위, 데이터 규모는 정해지지 않았다.
> 위 이해가 틀렸다면 답변 섹션에 바로잡아 주세요.

## 질문

### Q1. [사용자] 이 서비스의 주 사용자는 누구인가요?
- (a) 개인 사용자 1명 (나만의 레시피/식재료를 기록·관리하는 개인용)
- (b) 여러 일반 회원 (각자 자기 레시피/재료를 관리하는 다수 가입자)
- (c) 팀/가족 등 공유 그룹 (여러 명이 같은 레시피·재료를 함께 관리)
- (d) 관리자가 콘텐츠를 등록하고 일반 방문자는 열람만 (예: 레시피 공개 사이트)
- (e) 기타: ___
- 기본 가정: (b) 여러 일반 회원 — 답이 없으면 이 가정으로 진행합니다

### Q2. [범위] 이번 버전(MVP)에 반드시 포함해야 하는 핵심 기능은 무엇인가요? (해당하는 것 모두)
- (a) 레시피 CRUD (제목·재료·조리 단계·사진 등록/수정/삭제)
- (b) 식재료 CRUD (재료명·분류·단위 등 기본 관리)
- (c) 식재료 재고/보유 관리 (수량, 유통기한 등)
- (d) 레시피 검색·필터 (재료·카테고리·이름 기준)
- (e) 보유 재료로 만들 수 있는 레시피 추천/필터
- (f) 기타: ___
- 기본 가정: (a)+(b)+(d) 를 MVP 필수로, (c)·(e)는 이후 단계(Should/Could)로 진행합니다

### Q3. [범위] 이번 버전에서 **제외**할(하지 않을) 기능이 있나요? (Non-goals 후보)
- (a) 장보기 목록/자동 쇼핑리스트 생성
- (b) 영양성분·칼로리 계산
- (c) 다른 사용자와의 레시피 공유/공개·댓글·좋아요 등 소셜 기능
- (d) 식단 캘린더/주간 식단 플래너
- (e) 외부 쇼핑몰·배달 연동
- (f) 특별히 없음 / 위 항목 중 일부는 포함하고 싶음: ___
- 기본 가정: (a)(b)(c)(d)(e) 전부 이번 범위에서 제외 — 답이 없으면 MVP는 레시피·식재료 관리 핵심만 다룹니다

### Q4. [사용자] 로그인·회원가입(인증)이 필요한가요?
- (a) 필요 (개인별 데이터 분리, 로그인 후 이용)
- (b) 불필요 (로그인 없이 누구나 사용, 데이터는 공용/브라우저 저장)
- (c) 열람은 자유, 등록·수정만 로그인 필요
- (d) 기타: ___
- 기본 가정: (a) 필요 — Q1이 다수 회원이면 개인별 데이터 분리를 위해 인증이 필요합니다

### Q5. [데이터] 레시피와 식재료를 어떻게 연동하고 싶으신가요?
- (a) 레시피에 재료를 자유 텍스트로만 입력 (연동 없음, 단순 목록)
- (b) 식재료 마스터 목록에서 선택해 레시피에 연결 (재료 재사용, 오타 방지)
- (c) (b)에 더해 보유 재고와 대조해 "부족한 재료" 표시까지
- (d) 기타: ___
- 기본 가정: (b) 식재료 마스터에서 선택해 연결 — 재료 데이터를 구조화해 검색·재사용이 가능하게 합니다

### Q6. [데이터] 예상 데이터 규모와 첨부(사진 등)는 어느 정도인가요?
- (a) 소규모 (레시피 수백 개 이하, 사진 선택적, 개인/소수용)
- (b) 중간 규모 (수천~수만 개, 사진 필수, 다수 회원)
- (c) 대규모 서비스 지향 (수십만 개 이상, 미디어 다수)
- (d) 아직 모름
- 기본 가정: (a) 소규모 — 답이 없으면 소규모 기준으로 범위·성능 목표를 잡습니다

### Q7. [제약] 이용 환경(플랫폼)과 특별한 제약이 있나요?
- (a) PC 웹 중심
- (b) 모바일 웹 중심 (주방/장보기 상황에서 휴대폰 사용)
- (c) PC·모바일 반응형 모두 대응
- (d) 일정/기존 시스템 연동/정책 등 제약: ___
- 기본 가정: (c) 반응형 모두 대응, 특별한 외부 연동·법적 제약 없음 — 다르면 알려주세요
