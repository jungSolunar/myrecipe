# 이슈 로깅 스킬

## 파일 위치·이름
`work/ISSUE-<YYYYMMDD>-<번호>-<짧은제목>.md`
예: `work/ISSUE-20260722-001-login-token-expiry.md`

## 리포트 템플릿
```markdown
# ISSUE-20260722-001: <제목>
상태: Open / In Progress / Resolved
심각도: Critical / Major / Minor
관련: US-00x, PR #, 커밋 해시

## 증상
- 무엇이, 언제, 어떤 조건에서 발생했나 (재현 절차 포함)

## 원인 분석
- 직접 원인 →  근본 원인 (5 Whys)
- 확인한 것 / 배제한 것

## 해결 방법
- 적용한 수정 + 왜 이 방법인지
- 검증 방법 (테스트/재현 확인)

## 작업 이력
- 2026-07-22 14:00 — 증상 확인, 로그 수집
- 2026-07-22 15:30 — 원인 특정 ...

## 재발 방지
- 추가한 테스트 / 모니터링 / 프로세스 변경
```

## 규칙
- Resolved 처리는 검증 방법이 기재된 경우에만 가능
- 같은 근본 원인의 재발이면 새 이슈 대신 기존 이슈에 이력 추가
