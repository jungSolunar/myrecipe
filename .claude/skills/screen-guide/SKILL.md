# 화면 가이드 스킬 (Screen Guide)

**목적**: "어떤 기능이 어느 화면 어디에서, 어떤 방식으로 동작하는가"를
버전별로 추적 가능한 하나의 기획문서로 정리한다.
릴리스 노트(무엇이 바뀌었나)나 user-flows(흐름도)와 달리,
**최종 사용자·팀원이 화면 기준으로 기능 위치를 찾는 참조 문서**다.

- 산출물: `docs/screen-guide.md` (단일 파일, 버전 누적)
- 소유자: **planner** (기획문서이므로). 구현 확정된 사실만 기록한다(추측 금지).
- 근거: 실제 라우트(`web/src/App.tsx`), 화면 컴포넌트, 릴리스 노트, PRD 수용 기준.

## docs/screen-guide.md 템플릿

```markdown
# 화면 가이드 (Screen Guide)

기준 버전: vX.Y.Z · 갱신일: YYYY-MM-DD
"어떤 기능이 어느 화면에서 어떻게 동작하는가"를 화면 기준으로 정리한 기획문서.

## 버전별 변경 이력 (화면 관점)
| 버전 | 화면 | 변경 | 관련 US |
|---|---|---|---|
| vX.Y.Z | 레시피 목록 | "만들 수 있는 레시피만" 토글 추가 | US-013 |

## 화면 지도 (IA)
- 경로 → 화면 이름 → 접근 권한(비로그인/로그인/본인) 요약 표 또는 트리

## 화면별 상세
### <화면 이름> (`/경로`)
- **경로 / 접근 권한**: `/inventory` · 로그인 필요
- **진입점**: 어디서 이 화면으로 오는가 (헤더 "내 재고" 링크 등)
- **주요 동작** (요소별로):
  | 동작 | 화면 위치 | 방식 | 조건/예외 | 관련 US | 도입 버전 |
  |---|---|---|---|---|---|
  | 만들 수 있는 레시피 필터 | 검색·필터 바의 토글 | ON 시 부족 0 레시피만·부족 적은 순 | 비로그인/재고 0건이면 비활성 | US-013 | v1.2.0 |
```

## 작성·갱신 규칙
- **화면 기준으로 조직한다**: 기능(US) 기준이 아니라 사용자가 보는 화면(경로) 기준으로 목차를 구성.
  한 US가 여러 화면에 걸치면 각 화면에 나눠 기록하고 관련 US로 상호 참조.
- **위치는 사용자가 보는 말로**: "SearchFilterBar 컴포넌트"가 아니라 "검색·필터 바의 토글".
  단, 근거 추적을 위해 필요 시 컴포넌트/파일을 괄호로 덧붙일 수 있다.
- **버전 꼬리표 필수**: 모든 동작 행에 "도입 버전"을 달아 언제 생긴 기능인지 추적 가능하게 한다.
  변경(동작 방식이 바뀜)도 변경 이력 표에 남긴다.
- **접근 권한 명시**: 비로그인 열람 가능 / 로그인 필요 / 본인만 등 게이트 조건을 화면마다 적는다.
- **비활성·예외 상태도 기록**: 토글 비활성 사유, 빈 상태(Empty), 권한 없음 안내 등 사용자가 만나는 상태를 빠뜨리지 않는다.
- **구현 확정 사실만**: 구현·릴리스로 확정된 화면만 기록. 계획 단계 화면은 넣지 않는다(PRD/백로그가 담당).

## 언제 갱신하나 (workflow 연동)
- 각 버전의 **G3(구현) 통과 직후**, 그 버전에서 추가·변경된 화면/동작을 반영한다.
- 릴리스 노트(`docs/releases/vX.Y.Z.md`)와 교차 검증: 릴리스가 언급한 화면 변경이 가이드에 모두 반영됐는지 확인.
- 갱신은 planner에 위임하고, 오케스트레이터는 실제 라우트·컴포넌트를 열어 위치 서술이 맞는지 직접 확인한다.
